## 踩过的三个坑（按出现顺序）

1. **容器步骤秒失败且无日志**：`build.sh` 的 tee 写到中段才启动，早期 apt 失败没落盘。
   → 脚本开头 `exec > >(tee "$WORK/out/build.log") 2>&1`，workflow 侧再 `| tee -a` 兜底。
2. **`TOP: unbound variable`**：`set -euo pipefail` 的 nounset 与 AOSP 9 的 `build/envsetup.sh` 冲突。
   → `cd $SRC` 之后 `set +u`（`mka` 也依赖，别急着恢复）。
3. **HTTPS 推送不稳**：`GnuTLS recv error (-110)` / 连接 136 秒超时。
   → 改用 SSH deploy key（API 自动挂载），22 端口稳定；推送秒过。

## 日志/产物回传机制

GitHub 的 run log 和 Artifact 都从 `objects.githubusercontent.com` 下发，本机不可达。
所以 workflow 在 job 结束（无论成败）把 `build.log` / `recovery.img` **force-push 到 `artifacts` 分支**，
本机通过 `gh-proxy.com` 取 raw 文件（约 30 KB/s，31 MB 约 15 分钟）。

```bash
# 完整镜像
wget -c "https://gh-proxy.com/https://raw.githubusercontent.com/Black-emmmm/C6-TWRP-Cloud/artifacts/recovery.img"
# 日志
wget -O build.log "https://gh-proxy.com/https://raw.githubusercontent.com/Black-emmmm/C6-TWRP-Cloud/artifacts/build.log"
```
